# Group Project – Overview

> Source: [Canvas – Group Project - Overview](https://baylor.instructure.com/courses/257917/pages/group-project-overview) (CSI 5324, Fall 2026)

Read the Project Problem Description carefully before you assign project roles and make the project plan.

The project is a **semester-long software engineering project including 3 iterations**. Each team will analyze, design, implement, test, deploy, document, and demonstrate a substantial **web-based software system**.

The primary purpose of the project is not simply to produce a working application. Teams are expected to demonstrate a **disciplined software engineering process**, including requirements engineering, system analysis, architectural and detailed design, implementation, testing, configuration management, issue tracking, deployment, documentation, and iterative improvement.

## Team & Collaboration Expectations

- Form a group of **4–5 members**. All team members are expected to participate throughout the entire project.
- Each member serves in different roles, but **everyone is a developer** implementing application features.
- Each student must take primary responsibility for **at least three substantial use cases** through their analysis, design, implementation, and testing.
- All members' coding work is tracked via **Git — commit history will be evaluated for your grade**.
- **Peer evaluation** will be conducted at the end of each iteration and is part of each member's grade.

## Software Engineering Expectations

Teams are expected to apply appropriate software engineering practices throughout the project, including:

- Requirements analysis
- UML modeling
- Architectural and detailed design
- Version control
- Issue tracking
- Automated testing
- Code documentation
- Deployment
- Traceability among requirements, design, implementation, and testing

Project documentation should evolve as the implementation evolves. The final documentation must accurately describe the completed system.

## Technical Expectations

The project must be implemented as a **web application**. It must be **Maven-based**, tested with **JUnit tests**, and use **Git (GitHub or GitLab) from the beginning**. There is no required programming language or framework, but the recommended technology stack is:

- Java with **Spring Boot / Spring MVC** for the backend
- **React** for the frontend
- A relational database such as **PostgreSQL or MySQL**
- **JUnit** or an equivalent automated testing framework
- Git with **GitHub or GitLab**
- **Google Cloud Platform** or another approved deployment environment

Alternative technologies are allowed when the team can provide an appropriate technical rationale; they must be properly documented during Iteration 1. The system should use a suitable **multi-layered architecture** with clear separation among presentation, business logic, persistence, and data management.

## Project Process

Three iterations, each presented to the instructor:

1. Analysis outcomes
2. Design outcomes, with implementation prototype
3. Implementation outcomes

**IMPORTANT:** Each member should be in charge of at least 3 use cases for their full analysis, design, and implementation/unit testing.

### Iteration 1 – Week 6: Requirements and Analysis

Define the project vision and scope, identify functional and nonfunctional requirements, develop user stories and use cases, create analysis models and interface wireframes, establish the project repository and issue tracking system, and produce an initial prototype.

### Iteration 2 – Week 10: Design and Development

Refine requirements and analysis, develop the system architecture and detailed design, implement a substantial working prototype, define the database design, and begin systematic automated testing.

### Iteration 3 (Final Deliverable) – Week 15 or 16: Implementation and Evaluation

Complete the application, integrate persistence and business logic, perform testing and quality assurance, deploy the system, finalize the documentation, and demonstrate the complete product.

Specific deliverables and presentation requirements for each iteration will be provided separately.

## Project Management

- Each project must use an **issue tracking / project management system** such as GitHub Issues, GitLab Issues, Jira, or Trello.
- Teams should maintain sufficient records to demonstrate project progress and individual contributions.
- At the end, each team should develop a **team website** to maintain all project materials and the application demo. Detailed requirements will be released separately.

## AI-assisted Development Policy

Responsible use of AI-assisted development tools (GitHub Copilot, ChatGPT, Claude, Cursor) is **allowed and encouraged**.

AI tools may assist with coding, testing, debugging, refactoring, documentation, and design exploration. However, the team remains fully responsible for the correctness and quality of all submitted work.

Students must be able to **explain the code, tests, architecture, and design decisions** associated with their project, regardless of whether AI assistance was used.
