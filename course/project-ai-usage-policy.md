# Project AI Usage Policy

> Source: [Canvas page "Project AI Usage Policy"](https://baylor.instructure.com/courses/257917/pages/project-ai-usage-policy?module_item_id=5544225), Modules → Team Project → Policies. Retrieved 2026-09-22.

Dr. Ren's framing: AI tools (Copilot, Claude, Cursor) are **engineering tools** in the team
project, **not learning shortcuts**. The [Group Project Overview](group-project-overview.md) puts
it more strongly — responsible use is "allowed and encouraged".

## Allowed

**Implementation support**

- Generate boilerplate or repetitive code
- Assist with UI implementation
- Suggest refactoring or code cleanup
- Help debug runtime errors or exceptions

**Productivity & exploration**

- Explore alternative implementations
- Ask conceptual questions about APIs or libraries
- Improve code readability and formatting

## Not allowed

**Replacing design thinking**

- Generating requirements, use cases or UML diagrams **without reasoning**
- Producing documentation text you do not understand
- Deciding system architecture without team discussion

**Bypassing learning objectives**

- Copying AI-generated analysis or design artifacts **verbatim**
- Using AI to "fill in" missing understanding during demos
- Relying on AI to explain your own project during the presentation

**Academic integrity violations**

- Submitting AI-generated content as your own without review
- Using AI to impersonate individual contribution
- Claiming understanding of features you cannot explain

## Constraints

- You must understand and be able to explain the code.
- The final system must be consistent with the documentation.
- AI use does not remove responsibility for correctness.

## How it is evaluated

Grading looks at consistency between documentation, code and demo; the ability to explain design
decisions, system behaviour and trade-offs; and traceability across SDLC artifacts.

> *"If you cannot explain your system, AI involvement does not excuse that. And you will receive
> partial credits in the project deliverable."*

If unsure whether a specific use is appropriate, ask early.

## What this means for Iteration 1

The risk is concentrated exactly where this deliverable's points are: use cases, the domain model
and the requirements are the artifacts the policy forbids generating without reasoning. Drafting
with AI assistance is fine; **submitting a diagram or a use case that its author cannot defend in
the 15-minute presentation is not**, and each member presents one of their own use cases.
